# 接口契约速查（v1.1）

> 来源：C 提供的《评测接口说明》。本页只做速查，冲突时以原文档为准。
> 用例的断言全部按本页写；字段改名 = 用例全红，所以改字段必须先通知测试侧。

## 1. 入口

```python
from src.api import run

result = run("检索增强生成中的引用幻觉检测方法")
```

**是可直接 import 的函数，不是 HTTP 服务。** HTTP 版（`:8600`，`POST /chat`）是可选项，
返回体与 `run()` 同构，只做「解析请求体 → 调 run → 序列化」。

可选参数：`stage_budget_s`、`timeout_s`、`use_cache`、`evaluate`、`use_retrieval`、
`policy`、`raise_on_error`。既可平铺，也可放进 `options`。

## 2. 返回的 16 个顶层字段

| 字段 | 类型 | 含义 | 测试怎么用 |
| --- | --- | --- | --- |
| `schema_version` | str | 当前 `1.1` | 结构兼容性判断 |
| `engine` | str | 固定 `research-assistant` | 横向评测区分 |
| `run_id` | str | `eval-YYYYMMDD-HHMMSS-xx` | 关联日志与 trace |
| `ok` | bool | 流程是否跑完 | **通过率分母** |
| `prompt` | str | 回显输入（已 strip） | 输入输出对齐 |
| `answer` | str | 报告全文 | 质量打分 |
| `tool_calls` | list | 按真实顺序排列 | 工具使用正确性 |
| `tools` | list | 去重保序的工具名 | 覆盖率统计 |
| `references` | list | 本次检索到的来源 | 引用溯源、命中率 |
| `citation` | dict | 引用质量指标 | **幻觉检测** |
| `self_eval` | dict/null | `evaluate=True` 时的内置自评 | 与外部打分交叉验证 |
| `stages` | list | 五阶段耗时与状态 | 性能分析 |
| `retrieval_notes` | list | 逐源失败原因 | 解释「为什么没来源」 |
| `usage` | dict | 耗时/工具数/来源数/长文标记 | 成本核算 |
| `warnings` | list | 降级但仍成功 | 这份结果要不要信 |
| `error` | dict/null | `{type, message, where}` | 失败归因 |

## 3. `tool_calls[]` 语义

```json
{"seq": 1, "name": "search_papers_web", "args": {...},
 "status": "ok", "duration_ms": 1832.4, "result": {"records": 6}}
```

四条约定：

1. `seq` 从 **1 连续递增**，是真实执行顺序，不是按名字排序。
2. **失败也留记录**：`status="error"` + `error` 字段。工具失败 ≠ 工具没被调用。
3. 参数不脱敏但截断（字符串 2000 字、列表 20 项）。
4. `result` 是摘要不是原始返回。

算「工具」的只有三个：`search_papers_web`、`retrieve_local_library`、`search_local_knowledge`。
**LLM 调用不算工具**，它在 `stages` 里。

## 4. `references[]` 语义

- `id` 与正文 `[n]` **严格一致**：正文 `[1]` 就是 `references` 里 `id=1` 的那条。
- `cited` / `cite_count` 是**正文**统计出来的（先剥离 `## 参考文献` 块再数 `[n]`）。
- `kind`：`web` / `local_library` / `skill` / `experience`。
- 本地文献带 `path`；技能带 `path` + `score`。

## 5. `citation` 指标

| 字段 | 含义 |
| --- | --- |
| `markers` | 正文引用标记数（去重） |
| `available` | 本次真实提供的来源数 |
| `valid` | 能对上号的引用数 |
| `fabricated` | 引用了不存在的编号（**幻觉核心指标**） |
| `faithfulness` | `valid / markers`，零引用时为 0 |
| `coverage` | 被引用到的来源占比 |

## 6. 失败语义（最重要）

> 除 `raise_on_error=True` 外，**任何情况都不把异常抛给调用方**。

| 场景 | `ok` | 关键字段 |
| --- | --- | --- |
| 空 prompt / 非字符串 | false | `error.type="InvalidPrompt"` |
| 超过 2000 字 | false | `error.type="PromptTooLong"` |
| 超过 `timeout_s` | false | `error.type="TimeoutError"` |
| 超过 `stage_budget_s` | false | `TimeoutError`，带阶段名 |
| **单个检索源失败** | **true** | `tool_calls[i].status="error"` |
| 全部来源失败 | true | `references=[]`，`citation.available=0` |
| 后处理失败 | true | `warnings` 非空，`answer` 照常 |
| 模型调用抛错 | false | `error.type` 为原始异常类 |

HTTP 层另有三个「请求没进门」的状态码，与 `ok` 无关：`400`（非法 JSON / 缺 prompt）、
`413`（>1MB）、`429`（并发超限，按 `Retry-After` 退避）。

**`ok=true` 不代表答得好，只代表流程跑完。** 质量由 `citation` 与外部打分判断。

## 7. 对测试的三条硬约束

1. **先看 `ok` 再断言内容**——`ok=false` 时 `answer` 可能为空，直接断言会误报。
2. **超长输入是「拒绝」不是「截断」**——不要写「截断后仍能答」的用例。
3. **工具失败不改 `ok`**——别把 `status=error` 当成整体失败。
